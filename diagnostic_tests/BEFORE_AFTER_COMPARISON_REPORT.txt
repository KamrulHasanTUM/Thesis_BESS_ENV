TESTING METHODOLOGY NOTES

Random Policy Baseline:
------------------------
Both tests used random policy (not trained agent) to establish baseline
behavior. This means:

1. 0% improvement/worsening rate is EXPECTED
   - Random actions don't react to grid state
   - This is correct for baseline testing

2. Metrics that matter for baseline:
   - SoC distribution (shows penalty/bonus effects)
   - Violation frequency (shows penalty strength)
   - Reward balance (shows relative component magnitudes)
   - Clipping rate (shows feasibility constraints)

3. Metrics that don't matter for baseline:
   - Congestion improvement rate (requires trained agent)
   - Episode rewards (no learning happening)
   - Action quality (random by design)

Purpose of Random Baseline:
----------------------------
- Verify reward components are functioning
- Measure relative magnitudes of penalties/bonuses
- Identify configuration issues before training
- Establish performance floor

Next Phase:
-----------
After configuration adjustments, train agent and evaluate:
- Learning curve (reward over time)
